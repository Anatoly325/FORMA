# Форма Учеватова Кая — исполняемый профиль FORMA 0.1.0

Этот документ описывает код поставки. RFC 0001 версии 0.0.7 описывает более широкую
архитектуру и не является обещанием, что все её механизмы уже реализованы.

## Программа и грамматика

Один исходник — один модуль без импортов. Он содержит объявления `record`, `fn`
и `tool`. `tool` отличается от `fn` доступностью через внешнюю типизированную
границу. Внутренние вызовы используют ту же функцию и те же контракты.

```text
program    := definition*
definition := "record" Name "{" (field ("," field)* ","?)? "}"
            | ("fn" | "tool") name "(" params? ")" "->" type contract* block
field      := name ":" type
params     := field ("," field)* ","?
type       := "Int" | "Text" | "Bool" | "Unit" | Name | "List" "<" type ">"
contract   := ("requires" | "ensures") expression ";"
block      := "{" binding* expression "}"
binding    := "let" name (":" type)? "=" expression ";"
```

Имена состоят из ASCII-букв, цифр и `_`, не начинаются с цифры. Имена записей
начинаются с заглавной буквы; функции, параметры и локальные имена — со строчной
или `_`. Дублирование и затенение локальных имён запрещены; `result` зарезервирован
для постусловий. Пробелы и `//`-комментарии семантически незначимы.

Выражения: целые и JSON-строки, `true`, `false`, `unit`, имена, `[a,b]`,
`Name { field: value }`, `value.field`, `list[index]`, вызовы, блоки,
`if condition { a } else { b }`, лямбды `x => expression` и `(a,b) => expression`.
У блока всегда есть завершающее выражение без `;`. `else` обязателен.

Приоритет от низкого к высокому: `||`; `&&`; `== !=`; `< <= > >=`;
`+ -`; `* / %`; унарные `! -`; вызов, поле и индекс. Бинарные операторы левоассоциативны.
Операнды и аргументы вычисляются слева направо. `&&`, `||` и `if` не вычисляют
невыбранную ветвь. Присваивания и изменяемых значений нет.

## Типы и значения

| Тип/механизм | Правило |
|---|---|
| `Int` | Точное целое; лимит профиля 4096 бит на значение. Выход за лимит — ошибка ресурса. |
| `Bool` | Только `true` и `false`; приведения чисел в логические значения нет. |
| `Text` | Корректный Unicode, без нормализации и сравнения с учётом локали. |
| `Unit` | Единственное значение `unit`, в JSON — `null`. |
| `List<T>` | Однородный неизменяемый список; длина ограничена профилем. |
| Запись | Номинальный тип: одинаковые поля не делают разные имена типов совместимыми. |
| Функция | Явные типы параметров и результата; локальные типы выводятся. |
| Лямбда | Тип параметров берётся из контекста вызова `map`, `filter`, `fold` и т. п. |

Типы функций могут выводиться для локальных значений и callback-функций, но
синтаксиса таких типов в публичных сигнатурах пока нет. Пустому списку нужен
ожидаемый `List<T>` либо аннотация `let xs: List<Int> = [];`.

`+ - * / %` и сравнения порядка работают только с `Int`.
Деление округляет к нулю, знак остатка соответствует делимому.
`==` и `!=` требуют одинаковых типов и сравнивают данные структурно.
Функции и списки функций сравнивать нельзя. Строки соединяются через `join`,
числа преобразуются в текст явным `text`.

Индекс начинается с нуля; отрицательный или отсутствующий индекс даёт `E_BOUNDS`.
Деление на ноль даёт `E_DIV_ZERO`. Эти ошибки останавливают текущий вызов.
Пользовательские `Result`/`Option`, обработка ошибок и `match` пока не реализованы.

## Стандартные операции

| Операции | Семантика |
|---|---|
| `map`, `filter`, `flat_map` | Обход слева направо, порядок сохраняется. |
| `all`, `any` | Обход прекращается при определении результата. |
| `fold(list, initial, callback)` | Левый свёрточный проход, callback получает `(acc, element)`. |
| `concat`, `contains` | Объединение списков и структурная проверка наличия. |
| `unique` | Сохраняет первое вхождение каждого структурно равного значения. |
| `sum` | Сумма `List<Int>`, для пустого списка — `0`. |
| `range(n)` | `[0, ..., n-1]`, `0 <= n <= listLength`. |
| `len` | Длина списка либо число Unicode code points в тексте. |
| `split` | Точное разделение строкой; пустой разделитель разделяет по code points. |
| `join`, `trim` | Соединение и удаление краевых пробельных символов по правилу Node.js. |
| `abs`, `text` | Модуль числа и явное преобразование `Int`/`Bool`/`Text` в текст. |

Полные сигнатуры выдаёт `help --json`. Пользовательских generic-функций пока нет;
параметрический вывод типов ограничен стандартными операциями.

## Контракты и гарантии

`requires` вычисляются перед телом каждого вызова, `ensures` — после него.
В постусловиях доступен `result`. Предикат должен иметь тип `Bool`.
Его исполнение расходует тот же бюджет, что и тело функции. Контракт может
завершиться ошибкой или исчерпать бюджет; бесконечная проверка не считается доказательством.

Все функции этого профиля чистые: синтаксиса и операций внешних эффектов нет.
Для одной версии, одинаковых входов и лимитов результат детерминирован, если
исполнение успешно завершается. Доказательства завершения и полной корректности нет.
Используемая Unicode-обработка закрепляется средой Node.js, поэтому версия среды
указана отдельно от версии интерпретатора.

`checked` обозначает выполненную статическую проверку, `guarded` — динамические
контракты, `tested` — пройденный конечный набор примеров. Поле `proof` равно `false`.

## JSON и CSV

Аргументы инструмента передаются объектом с точными именами параметров.
Лишние и отсутствующие поля отвергаются на всех уровнях. Все выходные `Int`
кодируются десятичными строками, например `"123"`. Вход также допускает безопасные
JSON-целые в диапазоне `[-9007199254740991, 9007199254740991]`.

Строковая форма целого: `0` либо необязательный `-` и ненулевая цифра с остальными
цифрами. `"01"`, `"-0"`, `"1.5"` не являются корректными строками `Int`.
При чтении JSON-файлов проверяется исходная запись каждого числового литерала;
дроби, экспоненциальная запись и небезопасные числовые литералы отвергаются до
потери точности. Большие числа необходимо передавать строками.
JS API `run` получает уже разобранные значения и не может восстановить точность,
потерянную вызывающим кодом до передачи данных.

`describe` возвращает JSON Schema структуры. Дополнительные ограничения ресурсов,
Unicode, лексической записи чисел и пользовательских предикатов проверяются средой;
схема не заменяет эти проверки.

CSV: UTF-8, необязательный BOM, разделитель `,`, заголовки, кавычки `"`, удвоенные
кавычки внутри поля, переводы строк внутри кавычек, окончания строк LF/CRLF/CR.
Заголовки уникальны и в точности соответствуют полям заданной плоской записи.
Типы импорта: `Text`, `Int`, `Bool`; логические ячейки — только `true`/`false`.
Пробелы и регистр ячеек автоматически не исправляются. Пустая ячейка `Int` ошибочна.
Пропущенные поля и строки неверной ширины отвергаются.

`csv-inspect` возвращает до пяти строк и признак усечения. Импорт и экспорт файлов
выполняются CLI; исходник FORMA доступа к файловой системе не получает.

## Ограничения исполнения

| Ограничение по умолчанию | Значение |
|---|---:|
| Шаги интерпретатора и начисления за стандартные операции | 1 000 000 |
| Глубина вызовов | 96 |
| Глубина вычисления выражений | 256 |
| Элементы одного списка | 10 000 |
| Длина одной строки, UTF-16 code units | 65 536 |
| Биты целого | 4096 |
| Глубина входных/выходных данных | 64 |
| Узлы входных/выходных данных | 100 000 на обход |
| Размер исходника | 256 KiB |
| Размер CSV | 1 MiB |
| Размер JSON-файла | 4 MiB |

Доступный через CLI `--fuel` может только уменьшить бюджет. JS API позволяет
уменьшать остальные лимиты. Их увеличение требует нового профиля реализации.
В fuel учитываются исполнение, контракты, обработка входа и кодирование результата.
Это детерминированный счётчик работы, не токены LLM, не точный CPU-профиль и не
гарантия максимального времени или памяти всего процесса. Изоляция в отдельном
процессе/контейнере и жёсткое ограничение времени остаются задачей внешнего раннера.

## Представление и изменения

Хранится нормализованное синтаксическое дерево модуля: расположение в исходнике
и идентификаторы диагностик исключаются из хеша. Порядок определений сохраняется.
Комментарий или форматирование не меняют семантическую часть; перестановка определений
может изменить хеш. Эквивалентность произвольных программ не распознаётся.

Логический идентификатор функции — `fn:имя`, записи — `type:Имя`.
Идентификаторы выражений — пути в дереве конкретной ревизии. Они не обещают
стабильности после вставки узлов. Полного графового редактора, переименований
с сохранением идентичности и инкрементальной проверки пока нет.

Артефакт содержит версию интерпретатора, выбранный инструмент, нормализованную
программу и набор приёмочных случаев. Ревизия — SHA-256 канонического JSON всего
этого содержимого; изменение набора случаев тоже создаёт новую ревизию.
Версия Node.js не включена в хеш; для повторения среды используется `.node-version`.

`register` выполняет статическую и приёмочную проверку, затем создаёт первую
принятую ревизию. Новый кандидат поддерживает только `replace_body` существующей
функции. Сигнатуры и контракты через этот API менять нельзя. После замены целиком
проверяются модуль и сохранённые случаи; новые случаи разрешено добавлять.
Отчёт прошлого кандидата автоматически не переносится на новую программу.

`propose` не меняет текущую принятую ревизию. `accept` сверяет ожидаемую базу,
повторно проверяет артефакт и случаи, затем меняет указатель каталога.
При конфликте нет автоматического выбора последней записи. Вызов по ревизии
разрешён только для принятых версий; прежние принятые версии сохраняются.
Прочие определения модуля при замене тела одной функции остаются неизменными.

Каталог локальный и предназначен для доверенного владельца. Записи защищены
эксклюзивным каталогом `.lock`; указатель заменяется через переименование
временного файла. При остановке процесса запись может оставить `.lock`.
Удалять его вручную следует лишь после проверки отсутствия работающего писателя.
Гарантий восстановления после потери питания, распределённого консенсуса,
многопользовательского разграничения и криптографической подписи здесь нет.
Хеш обнаруживает изменение содержимого относительно идентификатора, но не
доказывает авторство или доверие к человеку, контролирующему весь каталог.

## Сверка заказов

Ключ: точные `order_id` и `currency`, сравнение чувствительно к регистру.
`amount` — неотрицательное количество заранее согласованных минимальных единиц.
Проверяются непустой идентификатор и длина валютного кода в три code points;
справочник валют и масштабы валют не встроены.

Приоритет классификации: если на любой стороне ключ встречается более одного
раза, результат `ambiguous`, даже если другая сторона пуста. Затем отсутствие
заказа даёт `unmatched`, отсутствие оплаты — `unpaid`, равенство сумм — `matched`,
иначе `discrepancy`. Результат хранит исходные строки обеих сторон.

Порядок ключей: первые вхождения в заказах, затем новые ключи оплат. Порядок
внутри групп сохраняется. Сложность первого алгоритма квадратична по общему
числу строк; крупный вход может исчерпать fuel. Такой отказ является ожидаемым
ограничением этого прототипа, а не частично успешной сверкой.
