# Форма Учеватова Кая — FORMA 0.1.0

**Форма Учеватова Кая** — полное имя языка. Короткое техническое имя — **FORMA**,
расширение исходников — `.forma`. Название объединяет фамилию Анатолия Учеватова
и имя Кай, выбранное для общения с ИИ-ассистентом в этом проекте.

Главная идея — свобода работы ИИ: самостоятельное создание, применение и развитие
инструментов для выполнения задач. Основной автор и пользователь кода — ИИ-агент.
История названия и правила его употребления: `docs/NAME.md`.
Этот архив содержит работающий первый профиль: собственную грамматику, парсер,
проверку типов, интерпретатор и локальный каталог инструментов с версиями.
Инструмент сверки заказов и оплат написан на FORMA, включая алгоритм сопоставления.

Это реализация подмножества проектного RFC 0001 версии 0.0.7. Статус каждого
механизма указан в `docs/SPEC.md`. Уникальность названия не проверялась.

## Запуск за минуту

Нужен Node.js 24+. Проверено на **Node.js 24.19.0, Linux x64**; эта версия также
указана в `.node-version`. Установка npm-пакетов и доступ к сети не нужны.
Распакуйте архив и откройте терминал в каталоге `forma`:

```sh
node --test
node examples/demo.mjs
```

Первый запуск проверяет реализацию. Второй выполняет полный сценарий разработки
через CLI и сохраняет результаты в новом подкаталоге `.demo/run-*`.
Каждая команда демонстратора запускается отдельным процессом.

```sh
node src/cli.mjs help --json
node src/cli.mjs check examples/reconcile.forma
node src/cli.mjs run examples/reconcile.forma --input examples/input.json
node src/cli.mjs probe examples/core.forma --expr 'factorial(20)'
```

Для Windows замените одинарные кавычки вокруг выражения на двойные, если этого
требует используемая оболочка. Windows и macOS в этой поставке не тестировались.

## Что уже работает

- Статические типы `Int`, `Text`, `Bool`, `Unit`, именованные записи и `List<T>`.
- Неизменяемые значения, функции, рекурсия, условия, лямбды и операции коллекций.
- Точная целочисленная арифметика без преобразования сумм в `float`.
- `requires` и `ensures` с проверкой при исполнении; отдельные коды ошибок.
- Типизированная граница JSON, JSON Schema, строгий импорт CSV.
- Локальное сохранение, поиск по имени и типам интерфейса, повторный вызов инструмента.
- Замена тела одной функции с указанием базовой ревизии и повторной проверкой.
- Сохранение старых версий и отказ от принятия правки поверх изменившейся базы.
- Ограничение шагов интерпретатора, глубины вызовов и размеров данных.

Интерпретатор написан на JavaScript для Node.js. Исходник FORMA разбирается
собственным парсером и исполняется по дереву программы; генерации JavaScript,
`eval` и зависимости от Python в прототипе нет. Использование Node.js как
среды реализации само по себе не определяет семантику нового языка.

## Практический сценарий

В `examples/reconcile.forma` инструмент получает списки заказов и оплат, сопоставляет
их по точному ключу `(order_id, currency)` и возвращает пять групп: совпадения,
неоплаченные заказы, оплаты без заказа, различия сумм и неоднозначные ключи.
Повторяющиеся ключи не агрегируются и не выбираются произвольно.

`demo.mjs` выполняет следующие действия:

1. Показывает структуру двух CSV и импортирует их по объявленным типам.
2. Проверяет инструмент на 19 заданных случаях и регистрирует его.
3. В новом процессе находит и вызывает сохранённую версию.
4. Получает ошибку типа для некорректной правки.
5. Проверяет новое учебное требование: допустима разница в одну минимальную
   денежную единицу. Старый код этот новый тест не проходит.
6. Заменяет только тело `amounts_equal`; все 19 прежних и один новый случай проходят.
7. Принимает новую ревизию и проверяет, что старая по-прежнему требует точного равенства.
8. Получает `E_CONFLICT` при повторном принятии кандидата с устаревшей базой.

Допуск является демонстрационным изменением правила. Исходный `.forma` в архиве
по-прежнему требует точного равенства. Пример не определяет правила возвратов,
частичных платежей, обмена валют или бухгалтерского учёта.

## Работа агента

Агенту, который умеет запускать локальные команды, достаточно `src/cli.mjs`.
Все успешные ответы — JSON в stdout; ошибки — JSON в stderr и ненулевой код выхода.
Начальный контекст для агента находится в `AGENT_GUIDE.md`, а актуальный список
операций выдаёт `help --json`. Отдельный сервер MCP здесь пока не реализован.

```sh
node src/cli.mjs register examples/reconcile.forma --cases examples/reconcile.cases.json
node src/cli.mjs find --input-type Input --output-type Report
node src/cli.mjs call --tool reconcile_orders --input examples/input.json
```

Каталог по умолчанию — `.forma` в текущем рабочем каталоге. Чтобы не зависеть от
текущего каталога, передавайте один и тот же абсолютный путь через `--catalog`.
Повторная регистрация того же имени отклоняется; изменения проходят через
`propose` и `accept`. Демонстратор создаёт новый каталог на каждый запуск.

## Проверенное и ещё не доказанное

В поставке сохранены результаты **52 автоматических тестов** и демонстратора:
`docs/TEST_RESULTS.tap`, `docs/DEMO_REPORT.json`.
Проверены в том числе сохранение точности, границы данных, отрицательные сценарии,
два конкурирующих процесса записи и повторное использование в новом процессе.

Тесты не являются доказательством полной корректности. LLM-агенты в демонстраторе
не запускаются: это воспроизводимый скрипт, проверяющий доступный им рабочий цикл.
Расход токенов и преимущество перед Python ещё не измерялись.

В текущую реализацию не входят `Option`/`Result` и сопоставление вариантов, модули,
внешние эффекты, HTTP, FFI, GPU, Wasm, формальные доказательства, вызовы моделей,
переключение моделей и создание роя. Сверка использует простой алгоритм с
квадратичным ростом работы; это проверка механики языка, а не готовый обработчик
миллионов строк. Следующие этапы описаны в `docs/NEXT.md`.
